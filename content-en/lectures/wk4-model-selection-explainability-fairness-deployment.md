## Position in the Course

The final week, closing out the full CRISP-DM loop: from
[[wk3-modelling-imbalance-deep-learning]] we already have XGBoost + SMOTE + Hyperopt performing
well on cross-validation — WK4 asks the harder question: "does good CV performance actually mean

[[wk3-modelling-imbalance-deep-learning]] left open: is AUPRC measured on resampled data
trustworthy?

## Learning Objectives

After this lesson you can: (1) explain why a high CV score on resampled data may NOT reflect true
performance on real data; (2) use PCA to reduce dimensionality and choose the number of
components by % explained variance; (3) use t-SNE to visualise high-dimensional data; (4)
distinguish K-Means (requires K upfront) from DBSCAN (finds cluster count itself, detects noise);
(5) use SHAP to explain a black-box model both GLOBALLY and per individual PREDICTION (locally);
(6) measure and mitigate algorithmic bias with FairLearn via 3 different approaches
(in-processing, post-processing, manual threshold adjustment); (7) package an ML pipeline into
reusable functions, ready for deployment.

## Core Theory

### 1. High CV on resampled data ≠ true performance — the turning point of the course

This is the MOST IMPORTANT point of WK4, directly answering the warning raised in
[[wk3-modelling-imbalance-deep-learning]]. The 54-combination grid shows XGBoost + CTGAN
Oversampling winning with a 0.9639 cross-validation AUPRC — but when retrained and evaluated on
the REAL TEST SET (never resampled), AUPRC drops to just **0.7951**, even LOWER than XGBoost
trained on the ORIGINAL, never-resampled data (**0.8024** on that same test set). Cause:
synthetic samples generated by SMOTE/CTGAN tend to be "close to" and "easier to predict" than
real data, since they're generated FROM those very data points — CV measured on a set mixed with
these easy synthetic samples produces an artificially inflated score. Lesson: CV SCORES ON
RESAMPLED DATA MUST NEVER BE THE FINAL DECISION CRITERION — always confirm against a REAL,
independent test set that was never resampled.

### 2. PCA — compressing dimensions while retaining information by % of variance

[[pca-tsne-dimensionality-reduction]]: PCA finds axes (principal components) along the directions
of GREATEST data variation, ranked in descending order — keeping more of the top components
preserves more of the original information (variance). The notebook needs 10/19 components to
retain 95% of variance — meaning the 19 original features have considerable REDUNDANCY
(overlapping information), so the model doesn't need the full 19 dimensions to learn well.

### 3. t-SNE — non-linear visualisation, NOT used for training a model

Unlike PCA (linear, preserves global structure), t-SNE is a NON-LINEAR dimensionality reduction
optimised to preserve LOCAL structure (points close together in the original space stay close
after reduction) — very useful for "seeing" high-dimensional data by eye (2D), but
distances/density on a t-SNE plot carry no reliable quantitative meaning, and t-SNE doesn't
generalise to new data (must rerun from scratch) — so it's used only for exploration/
visualisation, not as a preprocessing step for a model like PCA.

### 4. K-Means vs DBSCAN — two different clustering philosophies

[[kmeans-dbscan-clustering]]: K-Means requires the cluster count K PREDEFINED (estimated via the
elbow method), assigns EVERY point to some cluster (no concept of "noise"), and assumes roughly
spherical clusters. DBSCAN does NOT require K upfront — it finds the cluster count itself based
on point DENSITY (`eps`, `min_samples`), and has a concept of NOISE (points belonging to no
cluster, labelled -1) — better suited when clusters have arbitrary shapes or the data contains
many outliers.

### 5. Anomaly detection — training only on the "normal" class

[[anomaly-detection]] (Isolation Forest, Local Outlier Factor, a hand-written Autoencoder) are all
trained ONLY on the majority class (`X_train[y_train == 0]`) — unlike ordinary classification
which learns from BOTH classes. Intuition: the model learns "what normal looks like", then flags
anything sufficiently "different" as anomalous — useful when the minority class is extremely rare
or previously unseen (the model doesn't need prior examples of it).

### 6. SHAP — opening the "black box", explaining why a model predicts what it does

[[shap]] computes each FEATURE's contribution to EACH prediction, based on Shapley value game
theory — the sum of contributions exactly equals the gap between the actual prediction and a
baseline value. **Global**: aggregate SHAP values across ALL data to see which feature matters
most OVERALL (`summary_plot`). **Local**: view the SHAP values for one specific row to understand
WHY the model predicted that row the way it did (`waterfall`) — important when a specific
decision needs to be justified (e.g. a loan rejection).

### 7. FairLearn — measure first, mitigate second, and three different intervention points

[[fairlearn]] starts with MEASUREMENT (`MetricFrame` — accuracy/precision/AUPRC/TPR split by
sensitive group), then MITIGATES only if a gap is found. 3 intervention points in an ML pipeline:
**in-processing** (`ExponentiatedGradient` — enforces the fairness constraint DURING training,
requires retraining), **post-processing** (`ThresholdOptimizer` — adjusts the classification
threshold AFTER the model exists, no retraining needed), and **manual** (choosing different
thresholds per group by hand, simplest but error-prone if chosen by intuition). There's no
"single correct constraint" — `DemographicParity` (equal positive-prediction rate across groups),
`EqualizedOdds` (both TPR AND FPR equal across groups), `TruePositiveRateParity` (only TPR equal)
suit different contexts.

## Worked Example

```python
from sklearn.decomposition import PCA
import shap
from fairlearn.metrics import MetricFrame, true_positive_rate
from fairlearn.postprocessing import ThresholdOptimizer

# 1. Confirm on the real TEST SET — don't just trust CV on resampled data
model_original = xgb.XGBClassifier(scale_pos_weight=scale_pos_weight).fit(Train_X, Train_y)
model_ctgan = xgb.XGBClassifier(scale_pos_weight=scale_pos_weight).fit(Train_X_ctgan, Train_y_ctgan)
print(average_precision_score(Test_y, model_original.predict_proba(Test_X)[:, 1]))  # 0.8024
print(average_precision_score(Test_y, model_ctgan.predict_proba(Test_X)[:, 1]))     # 0.7951 — lower!

# 2. SHAP — global + local explanations
explainer = shap.TreeExplainer(model_original)
shap_values = explainer.shap_values(Test_X)
shap.summary_plot(shap_values, Test_X, feature_names=feature_names)   # global
shap.plots.waterfall(explainer(Test_X.iloc[[0]])[0])                   # local, one row

# 3. FairLearn — measure first, mitigate second
mf = MetricFrame(metrics={'tpr': true_positive_rate}, y_true=Test_y,
                  y_pred=model_original.predict(Test_X),
                  sensitive_features=Test_X['binary__is_married'])
print(mf.by_group)   # reveals a TPR gap between married and not-married groups

optimizer = ThresholdOptimizer(estimator=model_original, constraints="demographic_parity",
                                predict_method='predict_proba')
optimizer.fit(Train_X, Train_y, sensitive_features=Train_X['binary__is_married'])
```

## Pitfalls & Practical Notes

- **Picking the "best model" via `max(dict, key=...)` without noticing `max` by default iterates
  over KEYS, not (key, value) pairs** — the original notebook makes exactly this mistake,
  printing "Extra Trees SMOTE" instead of "XGBoost CTGAN" (the real winner). Always use
  `max(dict.items(), key=lambda kv: kv[1])`.
- **Trusting a CV score on resampled data as the final number** — always reserve a confirmation
  step on a real test set that was NEVER resampled, before deciding to deploy.
- **Tuning (Hyperopt) then never re-confirming on the test set** — the post-tuning CV score is
  always higher than or equal to before, but that guarantees nothing about the test set if the
  tuning step also runs on resampled data.
